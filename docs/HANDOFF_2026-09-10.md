上午最后发现两个事件问题，**loop.py 的修正已全部落盘**：
1. `RUN_STARTED` 每个 run_id 只发一次——恢复不重发（run() 入口 `if pending is None: emit`；`pending` 变量已上移到状态重置之前）。
2. `_resolve_pending` 不再发 `TOOL_CALLED`——挂起时已发一次（沿用 P1 语义：未执行的调用也发 TOOL_CALLED），恢复只补 `TOOL_RETURNED`；跨进程由 EventStore 按 seq 接链。

正确的挂起→恢复事件链（同 run_id）：
```
RUN_STARTED, MODEL_REQUESTED, TOOL_CALLED, RUN_PAUSED, TOOL_RETURNED, MODEL_REQUESTED, RUN_COMPLETED
```

## 5. 设计决定记录（下午改代码/测试时保持一致）

- `approval` 只在恢复时有意义：True 执行挂起调用、False 回填 tool_error；head 调用恢复时**不再过 approval_gate**（决定已做出），remaining 调用重新过门（可能再次暂停）。
- 挂起时消息停在 `[..., assistant(tool_calls)]`，**不落 tool 占位消息**；恢复后回填结果。暂停时 save 照常执行（消息 + run 行都落库）。
- 恢复时 deadline 从恢复时刻重新起算（monotonic 跨进程无意义）；step/usage/tool_calls_used 从快照**累计而非重置**（全栈测试断言 step==2、usage==2/2 证明）。
- 挂起未决时 `chat()` 在入口查 `get_paused_run` 拒绝新消息；CLI/Web 生产路径无 approval_gate，不会触发暂停，行为不变。
- 恢复的 run 若在重启期间注册表变化导致工具不存在：按 `tool_error: unknown tool` 回填（`_resolve_pending` 已处理）。
