## 2. 用户定下的工作规则（必须继续遵守）

1. 先读现有代码和测试，再决定修改方案；修改前说明现状、根因假设、验证方式。
2. 保持公开 API 尽可能兼容；不重写无关模块。
3. 不引入 LangGraph / AG2 或完整多智能体平台。

5. 测试不得访问真实 LLM/网络：一律 `ScriptedModel` + `httpx.MockTransport` + 临时目录 SQLite。
6. **字符串黑名单不是安全隔离**；高风险工具保持禁用占位，真隔离属 sandbox 任务。

### 已完成：第二阶段任务③（P2-C，提交 `1f2a486 feat(phase2): run persistence + approval pause/resume`，2026-09-12）

- `state.py`：`RunState` 末尾新增 `pending_approval`（形状 `{"call": {"id","name","arguments"}, "remaining": [...]}`）；`RunStatus.PAUSED` 生效。
- `loop.py`：`ApprovalGate = Callable[[str, str, ToolContext], bool]` 注入 `AgentRuntime`；`run(state, approval=True/False)` 为恢复入口，挂起时带 user_input / 缺 approval / 无挂起却给 approval 均抛 `ValueError`。挂起时记录待审批调用 + 同响应 remaining 调用（保证每个 tool_call 最终都有结果回填）；批准则执行挂起调用，拒绝回填 `tool_error: tool '<name>' was not approved`；remaining 重新过门，可能再次暂停。
- **事件链语义（恢复/排查时必读）**：TOOL_CALLED 在挂起时即发（P1 语义：未执行的调用也发），恢复只补 TOOL_RETURNED；RUN_PAUSED 携带挂起调用数据；RUN_STARTED 每个 run_id 只发一次。同 run_id 的挂起→恢复完整链：`RUN_STARTED, MODEL_REQUESTED, TOOL_CALLED, RUN_PAUSED, TOOL_RETURNED, MODEL_REQUESTED, RUN_COMPLETED`。
- `miniclaw/session/run_store.py`：`SQLiteRunStore` 表 `runs`，主键 (三键, run_id)，只存运行元数据（status/step/tool_calls_used/usage_json/error/error_kind/pending_approval_json/时间戳）；**消息仍由 SessionStore 唯一持有**，恢复不重复写。`get_paused_run` 取最近一条 PAUSED。
- `service.py`：`chat()` 前置守卫（同会话有 PAUSED run → ValueError 提示走 resume）；`resume(*, tenant_id, user_id, session_id, run_id, approval)` 用 RunStore 快照 + SessionStore 消息重建 RunState（`persisted_messages = len(messages)`），同 run_id 继续；run 不存在/非 PAUSED → ValueError；无 run_store → RuntimeError。
- `factory.py`：`build_runtime` 新增 `run_store` / `approval_gate` 参数，自动建库规则与 event_store 一致（注入 store 的测试路径不默认创建）；`RuntimeBundle` 增 `run_store`。
- `skill_tool.py`：子运行 PAUSED 时返回 `"skill_error: sub-run paused awaiting tool approval"`。
- 恢复语义：deadline 从恢复时刻重新起算（monotonic 跨进程无意义）；step/usage/tool_calls_used 从快照**累计而非重置**；head 调用恢复时不再过 gate（决定已做出）。
- 测试 +18（`test_run_store.py` 6、`test_run_pause_resume.py` 12），基线 **116 passed**。CLI/Web 生产路径无 approval_gate，不会触发暂停，行为不变。执行过程记录见 `docs/HANDOFF_2026-09-10.md`（已完成历史使命，仅供追溯）。

## 4. 必须保持的核心契约（改动前自查）

1. **三键隔离**：一切存储访问带全 `tenant_id/user_id/session_id`；不存在只按 session_id 查询的路径；空键抛 `ValueError`（注意 `list_sessions` 只有两键，`_ensure_keys(*keys)` 按实际传入校验）。
2. **Runtime 无状态**：RunState 显式传入传出；网关只经 `ConversationService`，不得绕过。
3. **增量持久化**：`RunState.persisted_messages` 是 save 游标，`save()` 只追加增量，幂等；重启恢复不重复写入。
4. **失败语义**：模型异常/超限/取消 → FAILED + `error_kind`；工具异常（含未知工具/参数坏/超时/被过滤）不终止运行，以 `tool_error:` 消息回填；失败运行已产生的消息仍持久化。
5. **单一组装入口**：CLI/Web/Skill/后续 Job 都从 `build_runtime(config, *, model, store, skill_dir, on_event)` 拿 `RuntimeBundle`；`model/store` 注入点专供测试。
6. **技能单一路径**：`SkillAsTool` 经注册时捕获的同一 runtime 实例执行；子运行 `tool_names` 排除 `skill_*`。

## 5. 测试编写约定与已知坑

- `tests/conftest.py` 提供 `db_path` fixture；`asyncio_mode = "auto"`（async 测试函数无需装饰器）。
- **ScriptedModel 是共享队列**：父子运行（技能）共用一个模型实例时，脚本按实际消费顺序排列——父请求工具调用 → 子终答 → 父终答。忘记排顺序会出现 "no scripted response left"（历史上踩过，见 `test_skill_via_full_stack_parent_chat` 注释）。
- 断言"模型看到了什么"用 `model.requests`（每条是 Message 列表）；并发隔离断言用它做"请求纯净性"检查（见 `test_acceptance_phase1.py` AC1）。
- 截止时间/耗时测试用注入 clock（`make_clock`），不要真实 sleep；超时类工具测试 0.01~0.05s 以内。
- 导入写正常 `from x import y`；本会话曾四次写出 `__import__(...)` 反模式，均已在当次修正——**不要再犯**。
- `AgentRuntime` 的 `clock` 参数显式传 `None` 是合法的（回落 monotonic）。
- 新增 dataclass 字段一律放最后并带默认值（保持位置兼容）。

## 6. 建议的下一步（P2-D 具体开工方案；P2-C 方案已执行完毕，见第 3 节）

现状：审批钩子是 `AgentRuntime(approval_gate=...)` 裸函数（`miniclaw/runtime/loop.py` 的 `ApprovalGate`），判定发生在 `_process_calls` 的 allowed/unknown 检查之后；`tool_timeout_s` 是 RunLimits 全局默认；审计链 TOOL_CALLED/TOOL_RETURNED 已入 EventStore，但 `build_runtime` 自动建库时未暴露 `redact` 开关。P2-D 把散落的判定收敛成独立策略对象，并补齐审计暴露面。

1. 新增 `miniclaw/tools/policy.py`：`ToolRule`（mode=`allow`/`needs_approval`/`deny`、每工具 `timeout_s`/`output_limit` 覆盖、`network` 标记——标记本身是 P2-E sandbox 的输入，P2-D 只负责声明）+ `ToolPolicy.decide(name)`；默认策略全 allow（既有 116 测试零回归）。
2. 切片 A（判定收敛）：`build_runtime` / `AgentRuntime` 接受 `tool_policy`；deny → 沿用 `tool_error: tool '<name>' is not permitted` 回填、不执行（与现有 "not allowed in this context" 同语义）；needs_approval → 接到现有暂停路径。`approval_gate` 参数保留兼容（测试在用）：gate 与 policy 任一判定需审批即暂停，policy.deny 优先短路。
3. 切片 B（执行约束）：每工具 `timeout_s` 覆盖 RunLimits 默认值（`_execute_tool` 取 min 规则值/全局值）；`output_limit` 截断结果并追加 `...[truncated]` 标记。
4. 切片 C（审计暴露）：`build_runtime(..., redact_events=False)` 透传给自动创建的 `SQLiteEventStore(path, redact=...)`；测试断言脱敏后事件无 `arguments`/`content` 但保留 name/call_id/ok——审计可读且不留敏感负载。
5. 测试 `tests/test_tool_policy.py`：验收断言用 ScriptedModel + 计数工具——deny 与未审批两条路径 `calls == 0`；再补 policy→PAUSED、截断、脱敏。全量回归（116 + 新增）后提交 `feat(phase2): tool policy + audit redaction`。
